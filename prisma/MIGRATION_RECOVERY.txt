Prisma migrations (squashed baseline)
======================================

There is a single migration folder: 20260415120000_baseline_schema
It contains the full DDL for the current prisma/schema.prisma.

Deploy / Neon (empty or reset database)
---------------------------------------
1. Empty database (or DROP SCHEMA public CASCADE; CREATE SCHEMA public; + grants).
2. Deploy so `prisma migrate deploy` runs — it applies the baseline once and records it in _prisma_migrations.

If migrate deploy fails partway (P3009 / P3018)
-----------------------------------------------
See: https://www.prisma.io/docs/orm/reference/prisma-cli-reference#migrate-resolve

Or reset the DB again and redeploy.

Regenerating the baseline SQL (when schema.prisma changes a lot)
----------------------------------------------------------------
From repo root, with schema updated:

  npx prisma migrate diff --from-empty --to-schema-datamodel prisma/schema.prisma --script -o prisma/migrations/20260415120000_baseline_schema/migration.sql

Then commit. For existing DBs that already applied the old baseline, you need a NEW migration name + migrate diff from current DB state — or reset the DB. For live with no migration history preference, resetting Neon is simplest.

Optional: local dev without migrations
--------------------------------------
You can use `npx prisma db push` against a throwaway local DB. Production/live should still use `migrate deploy` with this one baseline so deploys stay repeatable.
